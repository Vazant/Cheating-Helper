# Карта агентов проекта

## Маршрутизация

| Роль | Когда использовать | Результат | Разрешения |
|---|---|---|---|
| `model-architecture` | Меняется провайдер, модель или назначение модели | Карта потоков и точек изменения | Только чтение |
| `groq-limits` | Меняются Groq-модели, квоты, fallback или rate limits | Актуальная матрица моделей/лимитов и алгоритм | Только чтение + официальные источники |
| `settings-quality` | Добавляются настройки или нет тестов для изменения | UI/state/storage схема и минимальные проверки | Только чтение |
| `prompt-runtime` | Меняется AI Profile, compiled prompt, session snapshot, history или latency | Полный lifecycle context/request, budget и точки оптимизации | Только чтение |
| `audio-pipeline` | Меняется microphone/system capture, PCM, VAD, STT или voice routing | Source matrix, audio pipeline, cleanup, ошибки и проверки | Только чтение |
| главный агент | Нужно принять решение, изменить файлы или объединить выводы | Подтверждённый план, реализация и проверка | Запись в пределах задачи |

## Общие ограничения

- До подтверждения плана сабагенты не редактируют код приложения.
- Каждый вывод должен ссылаться на конкретные файлы/функции; внешние факты — на первичный источник.
- Если назначение модели неоднозначно, фиксировать вопрос, не выбирать самостоятельно.
- Не дублировать работу открытого upstream PR: сначала изучить его diff.
- Завершение задачи требует выполненных критериев и записанного результата проверки.

## Skills

- Проектный: `skills/cheating-helper-planner/SKILL.md` — обязательный workflow для планирования моделей, лимитов и настроек.
- `github` — issues, PR и upstream-анализ.
- `ponytail` — минимальный рабочий diff без лишних зависимостей.
- `skill-creator` — только при создании/изменении проектных skills.

Постоянные роли — маршруты работы, а не отдельные обязательные процессы. Главный агент назначает их существующим read-only subagents и не создаёт новый skill/agent, если одна из этих ролей уже покрывает запрос.
