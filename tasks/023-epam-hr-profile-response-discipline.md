# 023 — Исправить естественность и стабильность EPAM HR Call

Статус: `IN_PROGRESS`

Зависимость: `020`.

## Нормализованный запрос пользователя

Переписать профиль `EPAM HR Call`, потому что он отвечает слишком длинно и неестественно на small talk, без необходимости пересказывает CV и смешивает разные HR-вопросы. Ответы на одинаковые по смыслу вопросы должны сохранять одну фактическую позицию, а не каждый раз создавать новую историю.

## Наблюдаемая проблема

- На `How are you doing?` профиль выдаёт длинную карьерную презентацию вместо короткого человеческого ответа.
- На `Why do you want to change your job?` ответ добавляет причины выбора EPAM, хотя это отдельный вопрос.
- Повторная русская формулировка того же вопроса создаёт ещё одну версию ответа вместо устойчивого основного сообщения.
- Ошибочная STT-фраза `Why you want to change your world?` правильно распознаётся по смыслу как вопрос о смене работы, но ответ получается слишком уверенным и расширенным.

## Корневая причина

- `profiles/epam-hr-call.json` требует «normally 3-6 short sentences» без исключения для приветствий и small talk.
- Общий preset `concise` компилируется как обязательные 4–6 предложений (`src/utils/aiProfiles.js:33-37`) и стоит после профильных правил (`src/utils/aiProfiles.js:134-145`), поэтому подталкивает модель раздувать даже простые ответы.
- Текущие `MOTIVATION` и `answerRules` располагают личную мотивацию и интерес к EPAM рядом, но не запрещают смешивать их без соответствующего вопроса.
- В правилах нет явного принципа: использовать только минимально необходимую часть CV и не повторять самопрезентацию в каждом ответе.

## Модели и runtime

Provider, model IDs, язык, history budget, key rotation и fallback не меняются. Исправляется только compiled system prompt и его dependency-free проверки.

## Рекомендуемое поведение

### 1. Small talk

Приветствия, благодарность и `How are you?` — 1–2 естественных предложения, без опыта, проектов, мотивации, зарплаты или EPAM pitch.

Целевой пример:

> I’m doing well, thank you. It’s nice to meet you, and I’m looking forward to our conversation.

### 2. Причина смены работы

Использовать одну каноническую позицию и не добавлять EPAM, пока рекрутер отдельно не спросил `Why EPAM?`:

> I’ve been in the same environment for a long time, and I feel ready for the next step. I’m looking for professional growth, broader responsibility, and more varied projects. I’d like to keep developing while contributing the Java and Spring experience I already have.

Допускается естественная перефразировка, но факты и смысловые опоры не меняются.

### 3. Почему EPAM

Отдельный ответ только на вопрос об EPAM: международные enterprise-проекты, разные домены и возможности роста. Не заявлять знание конкретной команды, проекта или внутренних условий.

### 4. Пропорциональность

- Greeting/small talk: 1–2 предложения.
- Простой фактический HR-вопрос: 1–3 предложения.
- Motivation/fit: 2–4 предложения.
- `Tell me about yourself`: отдельный ответ до 60–90 секунд.
- Behavioral/STAR: подробнее только при наличии подтверждённого примера.

### 5. Контекст разговора

- Использовать предыдущие реплики для понимания короткого follow-up.
- Не повторять уже сказанную карьерную справку, если новый вопрос её не требует.
- При очевидной STT-ошибке выбирать наиболее вероятный HR-смысл только когда он однозначен; иначе задавать короткий уточняющий вопрос.
- Не придумывать новые причины, достижения или детали ради разнообразия формулировок.

### 6. Tell me about yourself

Для HR-звонка не использовать полный хронологический рассказ обо всех проектах и не выдавать отдельный список технологий. Ответ длительностью 60–90 секунд строится так:

1. Имя, текущая специализация, локация и почти 7 лет опыта.
2. Основной стек одной короткой группой: Java, Spring Boot, REST, persistence/database и delivery tooling.
3. Два доказательства опыта: Alanda — автоматизация и ускорение примерно на 60%; Carlsberg — надёжная миграция около 5 TB из AEM в AWS.
4. Тип ответственности, который нравится: end-to-end backend, сложные integrations и production reliability.
5. Короткое завершение: senior role, рост, более широкая ответственность и международные проекты.

Не включать в этот ответ подробности Cookiecutter/ChatGPT flow, throttling, XML parser, Smalltalk dependency graph и все остальные проекты одновременно. Эти детали сохраняются для follow-up вопросов. Названия технологий используются как подтверждение опыта, а не как длинный перечень ключевых слов.

Предоставленный пользователем длинный вариант полезен как банк фактов и заготовка для follow-ups, но не как единый ответ HR: он содержит несколько самостоятельных STAR/project stories и занимает значительно больше целевых 60–90 секунд.

Новые факты `Chrome extension`, `AudienceRate take-home` и `mentoring through code reviews` не переносятся в User Context до отдельного подтверждения пользователя.

### 7. Почему в CV нет более новых проектов

Подтверждено пользователем: работа продолжалась, но часть более свежих задач не была включена в CV, потому что Java не являлась там основной технологией. Среди таких обязанностей были Jaspersoft, настройка BPMN workflows и другая работа. При прямом вопросе профиль должен объяснять это как сознательную фокусировку CV на релевантном Java backend опыте, а не как перерыв в работе. В обычную самопрезентацию это объяснение не добавляется.

## Минимальный план после подтверждения

1. `DONE` Переписать `persona`, `answerRules` и `responseStyle` в `profiles/epam-hr-call.json`, разделив small talk, job-change motivation, Why EPAM, factual и behavioral вопросы.
2. `DONE` Уточнить общий `concise` preset: 1–2 предложения для greetings, до 3 для простого фактического ответа, 3–6 только когда вопрос требует объяснения.
3. `DONE` Добавить в profile test проверки обязательных правил: small talk без CV pitch, отдельная canonical job-change position и запрет смешивать её с Why EPAM.
4. `DONE` Проверить размер compiled prompt и отсутствие конфликтующих инструкций.
5. `DONE` Добавить одноразовую storage migration, которая автоматически заменяет только существующий профиль с точным ID `profile_epam_hr_call`.
6. `DONE` Выполнить profile/Groq/storage tests, syntax check, package и `git diff --check`.

## Критерии приёмки

- `How are you doing?` не вызывает рассказ о Java, Azati, Carlsberg, смене работы или EPAM.
- `Why do you want to change your job?` использует подтверждённые причины: рост, более широкая ответственность, разнообразные проекты; не критикует работодателя.
- `Why EPAM?` остаётся отдельным ответом и не подмешивается в job-change answer без соответствующего вопроса.
- Повторные формулировки сохраняют одинаковые факты и позицию, хотя могут звучать естественно, а не дословно одинаково.
- Короткий follow-up не запускает повторный полный рассказ о кандидате.
- Никакие отсутствующие в User Context факты не появляются.
- Язык ответа по-прежнему определяется только Speech Language.

## Требуется решение пользователя

Решено: использовать предложенную каноническую позицию и автоматически один раз заменить существующий профиль с ID `profile_epam_hr_call`.
