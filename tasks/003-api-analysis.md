## Фактическая архитектура

- Приложение Electron/Lit, версия 0.7.0; штатных тестов нет, `npm run lint` — заглушка.
- `src/utils/gemini.js` держит Gemini Live-сессию для аудио/транскрипции и уже отправляет полученный текст в Groq через `sendToGroq()`.
- Groq вызывается напрямую через `fetch('https://api.groq.com/openai/v1/chat/completions')` в streaming-режиме; новый SDK не нужен.
- Ключ хранится через `src/storage.js`, IPC-обработчики находятся в `src/index.js`, интерфейс ключа — в `src/components/views/MainView.js`.
- Скриншоты анализируются отдельно через Gemini/Gemma; Groq сейчас отвечает только на текст транскрипции.
- Local AI использует Ollama и локальный Whisper через `@huggingface/transformers`.

## Подтверждённые дефекты Groq

1. `getModelForToday()` первым выбирает отключённый 2026-07-17 `qwen/qwen3-32b`.
2. Лимиты оцениваются по символам и жёстко заданным дневным числам; реальные RPD/TPM заголовки игнорируются.
3. SSE разбирается по каждому сетевому chunk через `split('\n')`; JSON-событие, разрезанное между chunks, молча теряется.
4. При неуспешном запросе пользователь видит только HTTP-код, хотя тело содержит полезную причину (например, removed model).
5. Модель выбирается автоматически и не показывается пользователю; нет устойчивого fallback по ответу 429/404.
6. История ограничена количеством сообщений, а не контекстом/токенами выбранной модели.
