# 017 — Переключение AI Profile во время активной сессии

Статус: `TODO — FUTURE`

Зависимость: `016`.

## Нормализованное будущее требование

Позволить пользователю явно заменить AI Profile во время уже запущенной сессии, не смешивая незаметно разные system prompts, не переписывая историю и не меняя provider/model/API key.

Эту задачу сейчас не реализовывать.

## Предварительный безопасный контракт

- Редактирование или обычный выбор профиля меняет только настройку следующей сессии.
- В live UI появляется отдельное явное действие `Apply another profile to this session`.
- Перед применением показывается переход `X → Y` и предупреждение, что старые сообщения останутся в контексте; для чистого контекста предлагается `Start new session`.
- Main process сначала разрешает и компилирует target snapshot, затем атомарно меняет активную revision. Ошибка оставляет старую revision без изменений.
- Switch запрещён, пока text/vision/audio request находится in flight.
- История хранит append-only `profileTimeline`; старые turns сохраняют прежнюю revision, новые получают новую.
- UI меняет active label только после успешного ответа main process.

## Вопросы, которые нужно задать перед будущей реализацией

1. Должен ли live switch одновременно менять профиль по умолчанию для следующих новых сессий?
2. Должен ли switch менять только text/audio response prompt или также отдельные Vision/screenshot instructions?
3. Разрешать ли сохранение старой conversation history после switch как основной режим, либо первая версия всегда должна начинать новую сессию?

## Критерии будущей приёмки

- Обычное редактирование не меняет active revision.
- Confirmed switch влияет ровно на следующий запрос; cancel/error ничего не меняют.
- Provider, model и API key остаются прежними.
- Stale/concurrent switch отклоняется.
- Timeline переживает reload; старые turns не получают новый профиль задним числом.
- Новый сеанс не наследует случайно compiled prompt предыдущего.
