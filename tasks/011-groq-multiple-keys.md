# 011 — Управление несколькими Groq API keys

Статус: `DONE`

Решение пользователя: все ключи принадлежат пользователю; на этом локальном этапе хранить их без шифрования; при исчерпании квоты последовательно пробовать следующий ключ.

## Нормализованное требование

Добавить в настройки несколько принадлежащих пользователю Groq API keys. Хранить порядок ключей и автоматически запоминать следующий активный ключ после фактического `429`.

## Предлагаемая схема

```text
groqApiKeys: string[]
activeGroqApiKeyIndex: number
```

## Критерии приёмки

- Пользователь может сохранить несколько ключей в заданном порядке.
- Ключи хранятся в существующем локальном credentials JSON по явному решению пользователя.
- Старый одиночный ключ мигрируется автоматически.
- `429` переключает на следующий ключ; один запрос не пробует один ключ повторно и не зацикливается.
- После исчерпания всех ключей пользователь получает понятную ошибку.
- После успешной ротации следующий ключ сохраняется активным для последующих запросов.
- В логах нет значений ключей; выводятся только номера слотов.

## Результат анализа

Groq применяет лимиты на уровне organization/project, поэтому несколько ключей обычно разделяют одну квоту. Менеджер ключей проектируется для удобства и разрешённой отказоустойчивости аутентификации, а не для увеличения бесплатного лимита.
